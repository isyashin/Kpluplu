# Установка и сборка локального индекса (Windows)

## 1. Требования

- Git, Windows 10/11 и Python 3.13+; команда `python --version` должна работать в PowerShell.
- Локальная копия КонсультантПлюс с каталогом `BASE`, внутри которого лежат папки баз с файлами DT1 и DT2.
- SSD и не менее 8 ГиБ свободной RAM. Время индексации зависит от диска и состава базы.
- Место под индексы. Наш набор из 132 баз дал 114,32 ГиБ в четырёх файлах. Для первого полного прогона такого объёма подготовьте не менее 150 ГиБ свободного места: объединение создаёт временный `index_new.db`.

База и индексы в репозиторий не входят. Индекс содержит адреса страниц в файлах базы; после обновления файлов базы его нужно пересобрать.

## 2. Получение кода и зависимостей

```powershell
git clone https://github.com/isyashin/Kpluplu.git
Set-Location Kpluplu
.\scripts\setup.ps1
```

Скрипт создаёт `.venv` в папке проекта и устанавливает зависимости. Если PowerShell блокирует запуск локальных скриптов, откройте терминал с разрешённой для вас политикой выполнения.

## 3. Путь к локальной базе

В том же терминале укажите свою папку `BASE`:

```powershell
$env:CONSPLUS_BASES = "D:\путь\к\ConsultantPlus\BASE"
Get-ChildItem -LiteralPath $env:CONSPLUS_BASES -Directory | Select-Object -First 5 Name
```

Это значение действует в текущем терминале. В новом терминале задайте его снова; для запуска через OpenCode внесите тот же путь в `opencode-agent/opencode.json`.

## 4. Полная сборка индексов

```powershell
.\scripts\index_all.ps1
```

Скрипт делит базы на три группы, запускает индексацию и **ждёт завершения всех трёх процессов**. В другом терминале можно смотреть ход работы:

```powershell
Get-Content .\index_part1.log -Tail 5
Get-Content .\index_part2.log -Tail 5
Get-Content .\index_part3.log -Tail 5
```

Продолжайте только после сообщения «Все группы завершились успешно». При ошибке смотрите `index_part*.log` и `parallel_*.err`; неполные файлы нельзя объединять. Скрипт откажется запускать новую полную сборку поверх существующих `index_part*.db`.

Затем соберите общие карточки и связи:

```powershell
.\scripts\merge.ps1
Get-Item .\index.db, .\index_part1.db, .\index_part2.db, .\index_part3.db |
  Select-Object Name, @{Name="GiB"; Expression={[math]::Round($_.Length / 1GB, 2)}}
```

Результат: `index.db` с карточками и связями и три `index_part*.db` с полнотекстовым поиском. Все четыре файла нужны API. При повторном объединении скрипт сохраняет прежний `index.db` как `index_backup_*.db`, поэтому потребуется дополнительное место.

## 5. Запуск API и MCP

В терминале, где задан `CONSPLUS_BASES`:

```powershell
.\scripts\run_api.ps1
```

Команда держит API запущенным. Проверка в другом терминале:

```powershell
(Invoke-RestMethod "http://127.0.0.1:8741/api/health").ok
(Invoke-RestMethod "http://127.0.0.1:8741/api/search?q=налог").items.Count
```

Документация REST API: http://127.0.0.1:8741/docs. MCP-сервер для агента запускается отдельно:

```powershell
$env:CONSPLUS_BASES = "D:\путь\к\ConsultantPlus\BASE"
.\.venv\Scripts\python.exe mcp_server\run.py
```

При отсутствии API MCP запустит его сам. В режиме stdio отсутствие текста в терминале означает, что сервер ждёт запросов клиента.

## 6. Шаблон агента OpenCode (необязательно)

```powershell
xcopy opencode-agent D:\МойПроект /E /I
Set-Location D:\МойПроект
```

Перед `start.bat` замените в `opencode.json` три примера: путь к `.venv\Scripts\python.exe`, путь к `mcp_server\run.py` в клоне `Kpluplu` и `CONSPLUS_BASES` с вашей папкой `BASE`. OpenCode должен быть установлен отдельно.

## 7. Обновление базы

После изменения файлов КонсультантПлюс пересоберите все четыре индекса на новой копии проекта, затем проверьте API и переключите агент на неё. Текущий индексатор не обеспечивает безопасное обновление отдельных баз на месте: повторный запуск `index_fast.py` поверх существующей части оставляет старые записи FTS. Не используйте частично собранный индекс.
